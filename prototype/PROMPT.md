# Sepia 交互原型 · 设计提示词

> 用法：整段贴进 cowork design。产出物落 `sepia/prototype/`。

---

用 React 做一个可点击的交互原型（灰阶线框，不做视觉设计），产品叫 **Sepia**：一个单人本地的 markdown 笔记本，AI 以"批注"形式嵌在纸里。原型只验证交互手感，所有数据 mock，无后端。

## 产品心智（必须贯穿）

- **纸是主角**：界面就是一张纸，没有工具栏、没有 dashboard。侧边只有一个可全收起的文件树。
- **AI 不抢笔**：AI 只在被召唤时出现，写进正文必须经过用户"落笔"确认。没有自动补全、没有 ghost text。
- **痕迹克制**：每次 AI 对话在段落边缘留一枚小徽章（像 Figma 评论点），可一键全部隐藏还原白纸。

## 预置内容

编辑器里预放一篇中文技术博客草稿（主题：SDF 平滑合并，约 8 段，含一个 ```glsl 代码块、一个 ```mermaid 块、一张图片占位），让每个场景都有真实文字可操作。

## 要做的 12 个场景（顶部 stepper 可跳转，也能按顺序连续走完）

1. **W1 冷启动**：打开即上次的纸，光标已就位；右下角一枚小灰点表示"Agent 启动中"，3 秒后变实心（就绪）。无任何弹窗。
2. **W2 书写态**：模拟 live preview——`## 标题`、`**加粗**` 显示为排版效果，点击进入该行时露出 markdown 源码，移开复原。
3. **W3 图片**：模拟 ⌘V 粘贴（按钮触发即可），图片出现在纸上，下方小字显示落盘路径 `1mg/2608021030-sdf.png`。
4. **W4 `/` 组件菜单**：在空行输入 `/` 弹出菜单，仅三项：textdiagram、shader、image。选 textdiagram 插入 mermaid 块，编辑时是代码、失焦渲染成图（渲染可用占位图）。
5. **W5 shader 块**：```glsl 块旁边有一个运行中的预览区（用动画占位表示"实时渲染中"），代码可编辑。
6. **W6 markup 浮层**：选中一段文字按 ⌘K（或按钮），**原地展开浮层**（不是侧栏）：一个输入框 + 当前模型名小标签。输入指令"把这段说人话"。
7. **W7 diff 预览**：模拟流式输出（打字机效果，2 秒）后展示 diff：原文划线、新文对照。浮层内可以：继续追问（同一线程再来一轮，diff 更新）、下拉切换模型后重试、Esc 中断流式。底部两个按钮：**落笔** / 放弃。
8. **W8 落笔与徽章**：点落笔 → 正文替换（有一个 200ms 的柔和过渡）→ 浮层收起 → 该段落右缘浮现一枚小徽章点。
9. **W9 `@` 引用选择器**：正文中输入 `@` 弹出即时搜索列表（mock 五篇旧文文件名），选中插入引用。
10. **W10 一键还白**：快捷键 ⌘⇧H（或按钮）切换：徽章全隐 ↔ 全显。两种状态要能来回切，感受"纸变白"的瞬间。
11. **W11 线程面板 + 徽章展开**：点击徽章或打开右侧面板：本篇所有对话线程列表；点开一条显示完整对话过程 + 那段的 before/after diff。列表底部有一条置灰的"孤儿线程"（锚点失效示例）。
12. **W12 Agent 缺席**：一个开关模拟 opencode 不可用：顶部出现一条细提示线"Agent 缺席"，⌘K 唤起时说明原因，**其余一切功能照常可用**。

## 交互细节约束

- 快捷键：⌘K 唤起 markup、⌘⇧H 徽章开关、Esc 中断/关浮层、`/` 与 `@` 行内触发（都提供按钮兜底，方便鼠标走查）。
- 徽章：直径 ≤ 8px 的小点，悬停微放大，不放数字、不放头像，克制到几乎看不见。
- markup 浮层宽度与正文栏同宽，从选区下方展开，推开下文而不是遮盖。
- 全部灰阶线框，不做视觉设计；仅徽章和"落笔"按钮允许用一个强调色。中文文案。**圆角、配色、字体等样式不作约束——视觉风格待线框走查完成后再定（D-33）。**
- 性能感模拟：冷启动场景瞬时呈现；流式输出用打字机；落笔替换要有"轻"的手感。

## 技术要求

React 单页应用，组件按场景拆分；假编辑器用 contentEditable 或分段 span 实现即可（不必引入真实编辑器库）；所有 AI 响应用预写的 mock 文案；状态用一个简单的场景状态机管理，支持 stepper 跳转与 happy path 连播。

## 增量修订 v2（2026-08-02 原型走查后）

对现有原型做两处修改：

### 1. living editing：修正语法揭示粒度（替换原 W2 行为）

删除"点击段落→整段变 markdown 源码"的行为。没有渲染态/源码态两个模式，永远是同一层文本，装饰随光标细粒度开合：

- 揭示粒度 = **光标所在的行内元素**，不是整段。光标进入一个加粗词，只有那一对 `**` 淡入显现（灰色、比正文小半号），词保持加粗渲染；光标离开，`**` 淡出
- 标题行：光标在该行时行首露出 `## `（灰色），其余保持大标题渲染
- 选区跨多个元素时，选区范围内所有标记同时露出，方便精确编辑
- 块级组件（代码块/mermaid/shader/图片）保持原逻辑：聚焦进代码、失焦渲染
- 标记显隐用 ~120ms 淡入淡出，不许跳动、不许引起文字重排抖动

### 2. 增加 markdown 标准快捷键

全部是"包裹/解包"式 toggle（选中文字则包裹或去包裹；无选中则插入成对标记、光标停中间）：

- ⌘B 加粗 `**…**`、⌘I 斜体 `*…*`、⌘E 行内代码 `` `…` ``
- ⌘1 ~ ⌘6 标题级别切换，⌘0 还原正文
- ⌘⌥C 代码块、⌘⌥Q 引用块、⌘⌥U 无序列表、⌘⌥O 有序列表
- ⌘⇧K 插入链接 `[文字](url)`（**⌘K 保留给 AI markup，不要动它**）
- Enter 在列表项内自动续列表符，空项再回车退出；Tab / ⇧Tab 列表缩进
- 底部加一条可折叠的快捷键提示小字，验证可发现性

## 增量修订 v4（2026-08-03）· markup 浮层按阶段发家具

**问题**：当前 markup 浮层一个输入框被 6 个控件包了 3 行（顶部「MARKUP 段落」标签 + 模型选择器 + Esc 按钮，底部「Enter 发送 · Esc 关闭」提示 + 建议 chip + 发送按钮）。其中 Esc、发送各说了两遍，标签在陈述用户三秒前刚做过的动作。业界（Cursor ⌘K / Notion AI / Apple 写作工具）的共识是**两层结构：第一层给动词，第二层才给自由输入**，且家具跟着阶段走。

### 阶段一 · 唤起（⌘K 按下）

浮层里**只有两样东西**：

1. **一行输入框**，placeholder 承担全部提示（如「告诉 Sepia 你想怎么改…」）
2. 输入框下方**一列动词**（4 条左右，键盘上下选择，Enter 执行）

删除以下全部元素：「MARKUP 段落」标签、右上 Esc 按钮、模型选择器、底部「Enter 发送 · Esc 关闭」提示行、「填入…」建议 chip、发送按钮。**Enter 就是发送，Esc 就是关闭，不需要按钮复述。**

**动词随选中对象变化**（这才是原标签该做的事——不是显示你选了什么，而是让菜单反映你选了什么）：

| 选中对象 | 动词 |
|---|---|
| 普通文字 / 段落 | 说人话 · 更短 · 换个说法 · 改语气 |
| 代码块 | 加注释 · 解释这段 · 重构 |
| 图片 | 改说明文字 · 换标题 |
| 标题行 | 起个更短的 · 换个角度 |
| 引用块 | 展开 · 精简 |

**一开始打字，动词列表即消失**（变成纯输入）；清空输入则动词列表回来。

### 阶段二 · 生成中

输入框变成一行流式状态（如「正在改写…」+ 流动指示），右侧一个「停止」。除此之外无任何控件。

### 阶段三 · 出结果

**这时才出现家具**：diff 对照（原文划线 / 新文），下方一行操作：

- **落笔**（主按钮）· **放弃** · **重试**
- **模型切换收进「重试」**：重试按钮带下拉箭头，展开是模型列表（换个模型再来一轮）。换模型只在「对这版不满意」时发生，属于第三阶段，不属于第一阶段
- 追问输入框留在 diff 下方（同线程再来一轮）

### 验收

阶段一浮层里可数的控件 ≤ 1 个输入 + 4 个动词；改版前后各截一张图对比，家具数量从 6 降到 1。

## 增量修订 v5（2026-08-03）· 信息浮层与保存微反馈

**前提：不要做常驻底部状态栏。** 白纸哲学下多一条常驻家具就多一分噪音。源码里现有的 countLabel / hintLabel / hints 数据保留，但不渲染成底栏。

### 1. 信息浮层 · ⌘⇧I

（⌘I 已归斜体，故用 ⌘⇧I，与 ⌘⇧H 徽章开关、⌘⇧K 链接同族）

- ⌘⇧I 在**纸的右下角**浮起一块小卡片：非模态、不夺焦点、不推开正文
- 内容 4~5 行灰字：字数（N 词 · N 字符）、上次保存时间、当前 commit 短 hash、Agent 状态、文件相对路径
- 消失：再按 ⌘⇧I / Esc / **或一开始打字就自动淡出**（不需要用户去关它）
- 淡入淡出 ~150ms，半透明，不堆边框阴影

### 2. 保存微反馈 · 纸角一闪

- 触发：写盘完成那一刻（防抖 800ms 之后）
- 表现：纸的右下角一个极轻的高光/小点，淡入淡出约 600ms 后彻底消失。幅度小到「只在你恰好看那儿时才看见」；不移动任何布局、无 toast、无「已保存」字样
- **关键：平时无声，出事才留痕**——写盘失败或 git commit 失败时，同一位置变成**持久的警示点**（不消失），点开看原因。这个角落平时是呼吸，异常时才是路标

### 3. 快捷键提示的去处

不常驻。收进信息浮层底部的折叠入口，或干脆只留在「设置 > 快捷键」页。

## 增量修订 v7（2026-08-03）· 快捷键看板

**唤起**：⌘/ 打开，再按 ⌘/ 或 Esc 关闭；第二入口 = ⌘⇧I 信息浮层底部的「全部快捷键」。（不要用单键 `?`，编辑器里那是正常输入。）

**形态**：居中浮层，背景轻微压暗不全黑；宽约 720px；**一屏放下全部，不出现滚动条**——放不下说明快捷键太多，该砍功能而不是加滚动。

**结构**：按功能分类三列瀑布，每组小标题沿用设置页三级分组的下划线样式：

- **行内格式**：⌘B 加粗 · ⌘I 斜体 · ⌘E 行内代码 · ⌘⇧K 链接 · ⌘1–6 标题 · ⌘0 还原正文
- **块**：⌘⌥C 代码块 · ⌘⌥Q 引用块 · ⌘⌥U 无序列表 · ⌘⌥O 有序列表 · Tab/⇧Tab 缩进 · Enter 续列表（空项退出）
- **Agent**：⌘K 唤起改写 · Esc 中断 · ⌘⇧H 徽章还白
- **文件与视图**：⌘N 新建笔记 · ⌘W 关闭标签 · ⌘P 搜索笔记 · ⌘, 打开设置 · ⌘⇧I 信息浮层 · ⌘+点击 双屏打开引用
- **行内触发**：`/` 插入组件 · `@` 引用旧文

**每一行**：左功能名（正常字重）+ 右键位。键位用**键帽**：1px 边框、等宽字体；组合键之间留空隙不加「+」，⌘⌥C 即三个键帽并排。（键帽圆角与否属样式，待线框之后定。）

**三个让它舒服的细节**：
1. 顶部搜索框，输入即过滤（打「加粗」或「B」都命中）；过滤时不重排分组，只隐藏不匹配的行
2. **当前上下文可用的高亮、不可用的置灰**——markup 浮层开着时 ⌘B/⌘I 置灰，Esc/⌘K 高亮；一眼回答「我现在能按什么」
3. 底部一行小字「在 设置 › 快捷键 里可以改键」，点击跳转

**不要**：不要做成可编辑列表（那是设置页）；不要分页 / tab 切换；入场动画不超过 150ms。

## 增量修订 v8（2026-08-03）· 设置页新增项（对读 opencode desktop General 后）

只动设置浮层，其他界面不变。

### Desktop App › 通用

**「界面」组末尾追加一行**
- 触控板双指缩放 ｜ switch ｜ 默认开 ｜ 描述：允许触控板 pinch / ⌃滚轮 缩放正文

**「启动」组末尾追加一行**
- 启动时侧栏 ｜ segmented（记住上次 / 总是收起）｜ 默认「记住上次」｜ 描述：新窗口打开时左侧栏的初始状态

**新增一个三级分组「通知」，位置放在「启动」与「更新」之间**
- 后台任务完成时通知 ｜ switch ｜ 默认开 ｜ 描述：仅用于长任务；markup 这类十几秒的改写不发通知
- 出错时通知 ｜ switch ｜ 默认开 ｜ 描述：写盘失败、git 失败、Agent 崩溃

（**这一组里不要加提示音 / 音效相关的任何行**，见文末。）

**「更新」组调整**
- 「立即检查」按钮：点击后按钮文案依次变为 检查中… → 下载中… → 安装中…；无更新时显示「已是最新」
- 追加一行：更新后显示更新说明 ｜ switch ｜ 默认**关** ｜ 描述：装完新版弹一次 What's New

### Agent › 对话 › 上下文与发送

**在「发送快捷键」下方追加一行**
- 生成中再次发送 ｜ segmented（排队 / 立即转向）｜ 默认「排队」｜ 描述：AI 还在生成时你又发一条——排队 = 等这轮出完再跑；立即转向 = 打断当前生成，改按新指令重来

### 明确不要加（防止顺手补全）

- **提示音 / 音效**：不要音效选择器、不要音量、不要「完成时响一声」。写作是安静的活，视觉微反馈已经够
- **界面元素显隐开关群**：不要「显示文件树 / 显示命令面板 / 显示状态按钮 / 显示导航按钮」这类行。每加一个"要不要显示 X"的开关，就是承认 X 可能多余——正确做法是砍掉 X
- **终端 shell 选择**：Sepia 没有终端
- **新旧布局切换 / 旧版下线通知**：单人产品不需要迁移机制

## 增量修订 v9（2026-08-03）· 设置页重构为「笔 / 纸 / 伴」

一级仍是四个（Desktop App / 书写 / Agent / 输出），只重构二级与内容归属。

### 「书写」二级由「编辑器 / 文件与链接」改为三页：**笔 · 纸 · 伴**

划分轴 = 动作 / 载体 / 同伴：

- **笔** = 写字这个动作的能力 —— 判据「我敲键盘时会发生什么」
  三级分组：模式（默认编辑模式 / 细粒度语法揭示 / 揭示过渡时长）· 输入（智能配对 / 列表续行 / Tab 缩进宽度 / 拼写检查）· 保存与版本（自动保存 / 定时兜底 / 静默 commit 只读说明 / 保存微反馈）· 插入与组件行为（`/` 菜单包含哪些 / textdiagram 失焦渲染 / shader 实时预览 / shader 帧率上限）
- **纸** = 载体本身 —— 判据「这张纸长什么样、在哪、和别的纸怎么连」
  三级分组：版面（限制行宽 / 折叠标题 / 行号 / 打字机模式）· 字体排印（正文 / 等宽 / 字号行高 / 界面字体）· 纸面（配色 / 纸张底色 / 代码高亮主题 / 代码块语言标签 / textdiagram 主题 / 图片最大显示宽度）· 笔记属性（frontmatter 呈现 / 新建带 frontmatter / 模板）· 库与附件（笔记库 / 添加库 / 新建笔记位置 / 图片粘贴路径模板）· 链接（内部链接类型 / 始终更新内部链接 / 外链打开方式）· 窗口（启动时侧栏 / 始终聚焦新标签页 / 双屏默认比例 / 界面缩放 / 触控板双指缩放）· 删除（删除前确认 / 删除到）
- **伴** = Agent 陪写的方式 —— 判据「⌘K 之后它怎么表现」
  三级分组：唤起与动词（显示动词列表 / 动词列表按选中对象分组可增删改）· 上下文（上下文范围 / 允许读取引用文件 / 保留多轮上下文 / 双屏内容不自动加入的只读说明）· 生成与呈现（流式输出 / 发送快捷键 / 生成中再次发送 / 显示推理摘要 / 默认展开 diff）· 风格（系统提示词 / 回答长度偏好）· 痕迹徽章（落笔后显示徽章 / 记住还白状态 / 孤儿徽章提示 / 徽章悬停预览）· 记忆（启用 / 范围 / 从落笔中学习 / 确认方式 / 归纳窗口 / 已记住的三份档案 / 改写时附带记忆 / 存储位置 / 清空）

### 两处内容搬家

1. **一级「Agent」收窄为引擎**：只留 模型 · 技能 · 连接器 · ACP 四个二级页。原来的「对话」页与「记忆」页整体搬进「书写 › 伴」。（类比：打印机驱动设置 vs 文档打印选项。）
2. **外观类设置从 Desktop App 搬进「纸」**：配色、界面字体、界面缩放、触控板缩放、启动时侧栏、始终聚焦新标签页。Desktop App › 通用 只剩四组：语言 · 启动（启动时打开 / 登录时自动启动）· 通知 · 更新。

### 组件设置的拆分规则（重要）

同一个组件的设置要拆到两页：**行为归笔，样式归纸**。
- mermaid：失焦自动渲染 → 笔；图表主题 → 纸
- shader：实时预览开关、帧率上限 → 笔；（无样式项）
- 代码块：语言标签、高亮主题 → 纸
- 图片：粘贴路径模板 → 纸（库与附件）；最大显示宽度 → 纸（纸面）

## 增量修订 v11（2026-08-03）· 模型配置去掉 provider 概念

**问题**：opencode desktop 把模型配置拆成 provider + model 两级。provider 是引擎的内部结构，不是用户的心智；多模态（文生图 / 转写 / 文生视频）到来后按家分组更糟——用户要在 5 个 provider 里翻谁能画图。**能力才是分类轴，出处不是。**

「Agent › 模型」页重做，三个三级分组：

### 1. 可用模型

一个**扁平列表**，每行：模型名 ｜ **能力标签**（文本 / 视觉 / 出图 / 转写 / 出视频，自动带出不用用户填）｜ 出处灰色小字（`anthropic · 已登录`、`本机 ollama`、`自定义端点`）｜ 状态点 ｜ 移除按钮。

「添加模型」是**单一流程**，不要「先加提供方再选模型」两步：
搜索目录（打 claude / gpt / flux / whisper 都能搜到）→ 选中 → 若该来源尚无凭据就**就地要一次**（粘 key 或浏览器登录）→ 完成。另有一个「自定义端点」入口：base URL + key + 模型 ID。

### 2. 用途指派 —— 谁来干哪个活

一张表，每行一个用途、一个下拉：

- 改写（文本）· 快速改写（文本）· 配图生成（出图）· 语音转写（转写）· 视频生成（出视频，预留）· 不可用时回退（文本）

两条规则：
- **下拉按能力标签过滤**：纯文本模型不出现在「配图生成」候选里，用户配不错
- **候选里可以是模型，也可以是 MCP 工具**：用途绑定的是「谁来干这活」，不关心是模型调用还是工具调用。接了绘图 / TTS 类 MCP，它自动出现在对应用途的候选中

### 3. 登录与凭据（默认折叠）

列出已保存的登录（anthropic 已登录 / openai API key / ollama 本机无需凭据），可重新登录、移除；移除时依赖它的模型行变灰并提示。这一组默认折叠——正常路径是添加模型时顺带完成，用户不该主动来这里。

### 删除

原「提供方」分组、原「默认模型」「断网时回退本地模型」两行——前者并入用途指派的「改写」，后者并入「不可用时回退」。
