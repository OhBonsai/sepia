## 附录 A · 实施中自行判掉的设计空白（190 §0：判了记这里，不停下等人）

### A-1 · ⌘B 冲突（190 P1 点名要先裁）

**裁决：侧边栏让位，改 `⌘\`。⌘B 归加粗。**

理由是频次与性质：加粗是**写作动作**，一天按几十次，且 D-26 把它连同
⌘I/⌘E 一起定成了一组肌肉记忆，拆开一个就等于整组都要想一下；
侧边栏是**视图开关**，一天按几次。`⌘\` 不是凭空挑的——Obsidian 的左侧栏就是它，
用户的肌肉记忆不必从零建。

同一轮里 `⌘/` 也从 CM6 的 `toggleComment` 手里收了回来（Stage 7 已做）。
**新占一个 `Mod-x` 之前先看 `defaultKeymap` 里有没有它**——这条写进了
`editor/base.ts` 的 `APP_OWNED_KEYS` 注释。

### A-2 · `readDoc` 从 base.ts 迁到 bytes.ts

F2 的格式命令要读全文，而它是 `base.ts` 的下游；`readDoc` 留在 base 里就成了
`base → format → base` 的环，`check:deps` 的 no-circular 当场红。
迁到 `bytes.ts` 是**归位**而不是妥协：那个文件守的就是"不许全文规范化换行"这一条，
`readDoc` 存在的唯一理由也是它。base 里保留一行 re-export，既有 import 路径不破。

### A-3 · 主页与文件树的关系（P2 撞出来的）

**裁决：主页不挂文件树。** 原型的主页有它自己的左栏（workspace 列表 + 设置/帮助），
再并排一个文件树是原型里没有的东西，也让"我现在在哪儿"多了一处要看。

**连带一处必须跟着搬**：6b 真人轮修过的那句「这个文件夹里没有 .md」原本长在
**文件树的空态**里。主页不挂树之后，一个 `.md` 都没有的 book——用户就停在主页——
树的空态他一辈子看不到，而**那恰恰是最需要这句话的时刻**。已把它搬到主页。
`#7c` 因此仍然守着同一件事，只是守在新的位置上。

### A-4 · 最近列表：时间在行右侧，没有分组头

features 的 H4 写「按相对时间分组」，而原型 Layout 画的是**每行右侧一个时间**。
两者不矛盾：分组是**读出来的**，不是画出来的。先做成"分组头 + 行内时间"两处都画，
截图一看同一句话说了两遍——去掉分组头。

### A-5 · 设置页「未接上的项」怎么显示

**列出来、置灰、写「即将推出」**（190 P3 明写"不藏不删"）。理由值得记：
藏起来会给人「这个产品就这些功能」的错觉，而真相是「这些还没做」——
这两件事对用户完全不同，对我们更是。置灰的那些项同时是一张待办清单。

### A-6 · F18 与 D-39 冲突 → **按 D-39 走阅读模式，不做内嵌浏览器**

190 P5 的任务描述写的是「右侧区 WebContentsView：地址条 + 前后退 + 刷新」。
那是 `sepia-prototype-features.md` 里 F18 的**旧描述**——**D-39（2026-08-03）
已经把它否了**，且给了三条理由，每条今天都还成立：

1. iframe 会被 `X-Frame-Options` / CSP 拦掉相当一部分站点，失败还无法优雅检测；
   原生视图则要处理浮层让位。**阅读模式两个问题都不存在**（main 抓取，无同源限制）
2. 气质：作者点开外链是要看**这篇文章说了什么**，不是要一个带广告和 cookie 横幅的
   浏览器挤进纸里
3. 抽出的正文是 Sepia 可读的文本，**可以直接 `@` 进 markup 上下文**——
   浏览器里的内容对 Sepia 永远是黑盒

**决策记录优先于任务描述**：190 是"怎么干"的清单，D-39 是"做什么"的裁决，
后者是前者的上游。据此实现阅读模式，抽不出正文（SPA / 付费墙）时退回系统浏览器——
那条退路也是 D-39 写死的，且**它必须真能走**，所以桥上有 `reader.openSystem`。

连带：§3 预申报的 `api.browser.open/nav/close` 三项**作废**，实际是
`api.reader.read/openSystem` 两项。**不引 readability 库**：一段正则够用，而依赖是永久的。

### A-7 · 链接点击的三种去向

单击 book 内引用 = 当前 tab 跳转｜**⌘点击 = 右栏第二编辑器**（F16）｜
外链单击 = 右栏阅读模式，**⌘点击才交系统浏览器**（与设置「外链打开方式」联动）。
接在**捕获阶段**：CM6 自己也管点击，冒泡阶段轮到我们时光标已经被它挪走了。

### A-8 · F23 拆掉搜索之后，看板必须自己吃掉按键

人裁移除搜索框（2026-08-07）之后 `#3d` 当场红：**回车在纸上敲出了一个空行**。

根因是搜索框在的时候，焦点落在那个 input 上，"按键不漏到正文"这件事是白捡的；
拆掉之后焦点回到编辑器，一个**只读看板**的回车改了用户的字。
与 ⌘/ 被 CM6 绑成 `toggleComment` 是同一类事故，教训也是同一条：
**浮层是模态就得真的是模态**，不能靠"恰好有个输入框接着"。

现在看板开着时捕获阶段吞掉所有非修饰键；修饰键组合放行（⌘/ 关自己、⌘Q 退出照常）。

### A-9 · 纸是一张卡片（P7 逐屏对照的唯一结构性改动）

在浏览器里打开 `proto-2608031403.html` 逐屏对照，最大的一处结构差异是：
**原型里纸浮在一层更深的底上**——四周留白、圆角、与窗口边界之间有距离；
而我做到 P6 为止是满幅铺开的。

这属于 P7 明写要对的「布局与结构」，不是配色，所以改了：`.sepia-body` 用
`--sepia-surface` 当底，纸与右栏各是一张 `--sepia-paper` 的卡片，4px 圆角、
**无阴影**（Stage 2 已裁的 opencode 式克制）。文件树留在卡片之外——
它属于"窗口"，不属于"纸"。

同一轮对照还改了设置页：**一个三级分组 = 一张卡片**，行与行之间是细线，
而不是每行各自一张卡（原型 W19 的排布）。

**没有跟原型走的一处，记下来**：原型设置页的一级分组写作「智能体」，
