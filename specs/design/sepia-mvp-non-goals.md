# Sepia v1 反 MVP 清单

> **MVP 阶段不做的事**。每一条都附理由 + 推迟到哪 + 推迟代价。
>
> 使用规则：正在实现某个功能时对照本清单——出现在这里 = **stop**。
> 姊妹文档：[`sepia-mvp-happy-path.md`](./sepia-mvp-happy-path.md)（真理源）｜[`sepia-mvp-decisions.md`](./sepia-mvp-decisions.md)（决策记录）

## 一句话总结

> v1 = 「**一个能与 AI 交互的 markdown 书写器**」：一个人 + 一张纸 + 一个 Agent → 落笔与徽章。**任何加在等号左右两边的东西都先进本清单。**

## 表 2 · 持续诱惑 —— "看起来很合理"也不做

最容易在写代码写嗨的时候顺手加上的东西，每条都要警惕。

| 诱惑 | 看起来的合理性 | 实际代价 | v1 替代方案 |
|---|---|---|---|
| **Ghost text / Copilot 式自动补全** | "AI 编辑器都有" | **直接违反克制原则**：AI 主动往纸上写字 = Agent 抢笔。这是 Sepia 和 AI 编辑器们的立场分界线 | AI 只在被 ⌘K 召唤时说话 |
| **wiki 双链 `[[]]`** | Obsidian 惯性，知识网络感 | 非标准 md 语法，违反 A2；双链图谱是另一个产品的核心循环 | `@content` 服务 AI 上下文；给读者的链接用标准 md 链接；思维网走 trace（D3） |
| **book 级全文搜索** | "笔记软件标配" | 索引、增量更新、结果 UI，一整个子系统 | 篇内 ⌘F（CM6 自带）；book 级用 `@` 选择器的文件名搜索顶住；真要搜去终端 rg |
| **导出 / 发布按钮** | "写完一键发公众号" | 发布管线（OSS、doocs、封面）已在 Sepia 外成熟运转；v1 搬进来 = 维护两份 | v1 走现有 `publish-prep.sh` 管线（分镜 14）；**v2 已立项**：[`feature-v2-001-wechat-publish.md`](./feature-v2-001-wechat-publish.md)（OSS + shader→GIF + 公众号格式 + 底部链接 + 草稿直投） |
| **vim 键位** | 工程师情怀 | 键位体系 × 装饰层 × IME 三方打架，测试面爆炸 | 不做。CM6 有社区 vim 插件，v2 看是否开洞 |
| **提示音 / 音效** | "任务完成响一声，opencode 就有整套音效库" | 写作是安静的活；生成只要十几秒，响一声的打扰远大于告知价值。而且一旦有音效就要配音效库、配音量、配分类开关 | 视觉微反馈足够（保存纸角一闪 D-30、Agent 状态点）；后台长任务用系统通知，不用声音 |
| **界面元素显隐开关群** | "让用户自己决定显示哪些按钮"（opencode desktop 的 Advanced 段有一排：文件树 / 命令面板 / 状态 / 导航按钮） | 每加一个「要不要显示 X」的开关，就是承认 X 可能是多余的——正确的做法是砍掉 X，不是给它一个开关 | 用快捷键控制显隐（⌘⇧H 徽章、侧栏一键收起），不做设置项 |
| **Dark mode** | "都得有" | 双倍主题调试；视觉风格整体待定（D-33） | 只有 sepia 纸面一个主题 |
| **快捷键面板 / 命令面板 ⌘P** | "高级感" | 命令注册抽象；MVP 快捷键一只手数得完 | 快捷键写进空状态文案 |
| **表格可视化编辑** | md 表格难写 | 表格 UI 是无底洞 | 源码态写表格；⌘K 让 AI 排 |
| **AI 自动命名 / 自动摘要 / 自动打标** | "顺手的智能" | 每一个"自动"都是 Agent 抢笔的开始 | 文件名用户自己起；未来记忆模块统一考虑 |
| **成本 / token 显示** | 透明感 | 分散注意力；单人使用心里有数 | opencode session 里查 |
| **导出 PDF / 长图** | 分享方便 | headless chrome ≈ 100MB 包体 | 浏览器打开 md 渲染页 ⌘P |

## 表 3 · 范围说明：技术/运维取舍不在本文档

本清单只管**功能与使用习惯**。构建矩阵（win/mac/linux 打包走 GitHub Actions 之类）、自动更新、签名、CI、测试投入等技术/运维决策，在技术架构阶段另立文档——不在产品文档里预设做或不做。

仅两条与使用体验直接相关的范围约束保留在此：

| 约束 | 理由 |
|---|---|
| CM6 装饰层 MVP 只覆盖：标题、粗斜体、代码块、三个组件 widget | 表格/脚注/数学显示为源码（无害裸奔），后续版本补 |
| opencode 能力只透出 AgentBridge 的 5 个方法 | D-15；防止功能顺着 API 蔓延 |

## 表 4 · 最容易忘的边界（写出来防自己）

- ❌ 不在 UI 里暴露 opencode 术语——用户看到的是"Agent / 对话 / 徽章"，不是 session / provider / sidecar（模型名除外，C5 要用）
- ❌ 不做 onboarding 向导——空状态文案 + 快捷键提示就是全部引导（分镜 0 没有任何弹窗）
- ❌ 不做"AI 生成整篇文章"入口——Sepia 改写你写的字，不替你从零写（从零写去 opencode TUI）
- ❌ 不做徽章的"全部采纳 / 批量处理"——每次落笔都是一次亲手确认
- ❌ 不做设置项蔓延——设置永远三项（D-14/F2）；想加第四项先来本清单报到
- ❌ 不清洗 / 格式化用户的 md——包括保存时不 trim 空行、不统一列表符号（A2 的字节级承诺）
- ❌ 不把 trace 做成"用户要维护的东西"——它必须零感知积累，永远不弹"要不要整理你的思维链"

---

## 使用规则

1. 加功能前先查这里，在表里 → stop。
2. MVP 周期内每冒出一个新想法，当场决定「进 v1 脚本 or 进本清单」，不许悬空。
3. v1 跑通后总清算：被现实打脸的条目（比如"没有搜索真的活不了"）升格进 v2 spec。
