# Sepia 设置清单（完整版 · 朝最终目标）

> 2026-08-03 定稿结构。**这是完整产品的设置清单，不是 MVP**——MVP 由此衰减，本文不标阶段。
> 层级：**一级 = 侧栏分组**（四个，不可变）→ **二级 = 侧栏页面** → **三级 = 页面内分组标题** → 设置项。
> 组件类型词表：`switch` 开关 ｜ `select` 下拉单选 ｜ `segmented` 分段单选 ｜ `multiselect` 多选 ｜ `input` 文本框 ｜ `input(secret)` 密文框（钥匙串存储）｜ `number` 数字/步进 ｜ `slider` 滑杆 ｜ `textarea` 多行文本 ｜ `path` 目录/文件选择 ｜ `keybind` 快捷键录制 ｜ `list` 可增删条目列表 ｜ `button` 按钮 ｜ `button(danger)` 危险按钮 ｜ `readonly` 只读展示 ｜ `note` 静态说明

## 设置哲学

1. **零配置可用**：每项都有正确默认值，设置页是改喜好，不是装系统。
2. **存储**（D-22，已按 T-02 改判）：**单一应用级 `~/.config/sepia/config.json`**——字段树镜像本清单、只存与默认值的差异、容忍未识别字段；book 级覆盖等真实需求出现再加；凭据进系统钥匙串；记忆 `.sepia/memory/*.md`。
3. **刻意的空白**：没有 markdown 格式规范化（A2 字节承诺）；**没有任何 Agent 权限设置**（Agent 只输出内容，写文件与执行命令的能力不存在，是产品原则不是配置项，D-13）；没有提示音；没有「要不要显示 X 按钮」这类显隐开关群（D-34）。
4. **样式待定**（D-33）：圆角、配色、字体的具体取值等线框走查后单独定，此处只定「有哪些可调项」。

## 「笔 / 纸 / 伴」的划分轴（D-35）

「书写」一级下的三个页面，划分依据是**动作 / 载体 / 同伴**：

| 页面 | 管什么 | 一句话判据 |
|---|---|---|
| **笔** | 写字这个动作的能力 | 「我敲键盘时会发生什么」 |
| **纸** | 纸这个载体本身 | 「这张纸长什么样、在哪、和别的纸怎么连」 |
| **伴** | Agent 陪写的方式 | 「⌘K 之后它怎么表现」 |

两条推论：

- **组件按「行为归笔、样式归纸」拆开**。mermaid 失焦自动渲染 → 笔；mermaid 图表主题 → 纸。shader 实时预览开关 → 笔；代码高亮主题 → 纸。
- **「伴」与一级「Agent」分层**：Agent 一级只管**引擎**（模型 / 技能 / 连接器），伴管**引擎怎么陪你写**（唤起、上下文、呈现、痕迹、记忆）。类比：打印机驱动设置 vs 文档打印选项。

## 1.2 快捷键

顶部：搜索快捷键 `input` ｜ 恢复全部默认 `button`。每项 `keybind`（点击录制，冲突即时红字提示）。只读速查版是 ⌘/ 唤起的**快捷键看板**（D-32），本页是可编辑版。

**行内格式**：加粗 ⌘B ｜ 斜体 ⌘I ｜ 行内代码 ⌘E ｜ 链接 ⌘⇧K ｜ 标题 1–6 级 ⌘1–6 ｜ 还原为正文 ⌘0

**块**：代码块 ⌘⌥C ｜ 引用块 ⌘⌥Q ｜ 无序列表 ⌘⌥U ｜ 有序列表 ⌘⌥O ｜ 列表缩进/反缩进 Tab·⇧Tab ｜ 续列表·空项退出 Enter（`readonly`）

**伴**：唤起 markup ⌘K ｜ 中断流式输出 Esc ｜ 徽章一键还白 ⌘⇧H ｜ 切换模型 未指定

**文件与视图**：新建笔记 ⌘N ｜ 关闭标签 ⌘W ｜ 搜索笔记 ⌘P ｜ **打开设置 ⌘,** ｜ 信息浮层 ⌘⇧I ｜ 快捷键看板 ⌘/ ｜ 打开线程面板 未指定 ｜ 双屏打开引用 ⌘+点击（`readonly`）

**行内触发**：插入组件 `/` ｜ 引用旧文 `@`（两项 `readonly`，触发符不可改）

# 一级 3 · Agent（引擎）

> 只管引擎与生态；Agent 在纸上怎么表现，在「书写 › 伴」。
> **没有权限设置**：Agent 只输出内容，不能写文件、不能执行命令（D-13）。

## 3.1 模型

> **只有「模型」一个概念，不透出 provider**（D-36）。内部仍是 `providerID/modelID`，UI 层不暴露：出处只作为灰色小字，凭据收进折叠区。

**可用模型**（三级）

| 设置项 | 组件 | 默认 | 说明 |
|---|---|---|---|
| 模型列表 | list（每行：模型名 + **能力标签** + 出处灰字 + 状态点 · 移除 button） | 随 opencode 现有配置导入 | 能力标签：`文本` `视觉` `出图` `转写` `出视频`（由目录元数据自动带出，不需用户填）。出处如 `anthropic · 已登录` / `本机 ollama` / `自定义端点` |
| 添加模型 | button → 单一流程 | — | ①搜索目录（打 claude / gpt / flux / whisper 都能搜到）→ ②选中；若该来源尚无凭据，**就地要一次**（粘 key 或浏览器登录）→ ③完成。或选「自定义端点」：base URL + key + 模型 ID。**全程不出现「先加提供方再选模型」两步** |

**用途指派**（三级）—— 谁来干哪个活

| 设置项 | 组件 | 默认 | 说明 |
|---|---|---|---|
| 改写 | select（按能力过滤：文本） | 首个可用文本模型 | ⌘K markup 的主力；浮层内仍可临时切换 |
| 快速改写 | select（文本） | 同「改写」 | 短任务/低延迟场景，可指本机小模型 |
| 配图生成 | select（出图） | 未指派 | 文生图；**候选里同时列出具备该能力的 MCP 工具** |
| 语音转写 | select（转写） | 未指派 | 音频 → 文字 |
| 视频生成 | select（出视频） | 未指派 | v3+ 预留 |
| 不可用时回退 | select（文本） | 本机 ollama（若有） | 远端不可达时接管「改写」 |

> **能力标签驱动可选性**：每个下拉只列能力匹配的候选，纯文本模型不会出现在「配图生成」里——用户配不错。
> **候选可以是模型，也可以是 MCP 工具**：用途绑定的是「谁来干这活」，不关心它是一次模型调用还是一个工具调用。将来接绘图 / TTS 类 MCP，它自动出现在对应用途的候选中，不需要新造设置。
