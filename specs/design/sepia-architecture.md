## 1. 约束

架构的对错由这一节裁定。

### 1.1 性能预算

**Aha #1 白纸秒开**（底线型，优先级高于 Aha #2）

| 段 | 预算 |
|---|---|
| 冷启动 → 可写 | **< 1s** |
| 进程启动 → 窗口可见 | < 500ms |
| 窗口 → 上次的 page 渲染 + 光标就位 | < 500ms |
| 引擎启动 + 健康检查 | ≤ 5s，后台，不阻塞任何 UI |

**Aha #2 markup 落笔**（灵魂型）

| 段 | 预算 |
|---|---|
| ⌘K → 浮层就位 | < 50ms |
| 提交 → 首 token | < 3s |
| 首 token → 完整 diff | < 12s |
| 选中 → 完整 diff 全链 | **< 15s** |
| 落笔（替换 + 成对 commit + 徽章） | < 300ms |

**其余**：`/` 菜单 < 50ms ｜ `@` 选择器 < 50ms ｜ 图片粘贴 → 显示 < 200ms ｜ 模型切换 < 100ms ｜ 徽章/线程点开 < 300ms ｜ 2 万字长文输入无感、滚动流畅 ｜ 中文 IME 组合输入不被装饰层打断 ｜ 标记显隐不引起文字重排抖动。

### 1.2 不变量

任何设计不得违反。

1. **纸永远可写，Agent 可以缺席**。引擎不可用时 Sepia 是一个完整的 markdown 编辑器。
2. **文件即真相**。纯 .md + 标准围栏。精确表述是：**只重写用户当次编辑所触及的最小区间，未触及的字节逐字节保留**——不做全文规范化、不重排、不加私有语法。打开、保存、AI 落笔，都不得改动无关字节。
3. **AI 不抢笔**。只在 ⌘K 被召唤时说话，写入正文必经用户落笔。
4. **Agent 没有写权限**。工具全关 + 引擎侧 permission deny，双保险。
5. **只发明徽章与思维链**，其余概念一律映射到 opencode / git 既有机制。

### 1.3 非目标

多 book 并存 ｜ book 级全文搜索 ｜ 思维链 trace ｜ 记忆 ｜ shader 块 ｜ 设置 UI ｜ 代码签名与公证 ｜ 自动更新 ｜ 第二语种 ｜ 拼写检查 ｜ 打印与导出 PDF ｜ 崩溃上报与遥测 ｜ 远程备份 ｜ 视频嵌入。

## 2. 形状

### 2.1 进程

```
┌─ Electron main ───────────────────────────────────────────┐
│  窗口 / 菜单 / 原生对话框      ipc.ts（REST 风格 handler） │
│  GitService   ConfigService   AgentSupervisor（起停/健康） │
└────┬──────────────────────────────────┬───────────────────┘
     │ utilityProcess.fork              │ IPC（contextBridge 白名单）
┌────▼───────────────────┐   ┌──────────▼────────────────────┐
│ utilityProcess         │   │ renderer（React）             │
│  import opencode server│   │  CM6 编辑器宿主 · markup 浮层  │
│  Server.listen(...)    │◄──┤  线程面板 · Home · 状态点      │
│  cwd = book 根         │HTTP│  AgentBridge · api.ts         │
└────────────────────────┘+SSE└───────────────────────────────┘
```

- **main** 是唯一接触 OS 的进程：窗口、文件 IO、git、配置、引擎监督。**不缓存应用状态**（真相在文件），引擎端口与进程句柄是仅有的例外。
- **utilityProcess** 是引擎宿主。它崩溃不拖垮其他进程——这是不变量 1 的进程级兑现。
- **renderer** 跑在 sandbox + contextIsolation 下，**对外只有两条腿**：`AgentBridge`（HTTP+SSE 直连 127.0.0.1）与 `api.ts`（preload 白名单之上的唯一封装）。

### 2.2 真相住在哪

| 数据 | 真相所在 |
|---|---|
| 正文 | `.md` 文件——唯一真相，永不改写字节 |
| 版本 / diff / 历史 | git，不自建快照 |
| session / message | **opencode**，Sepia 不复制，只存 sessionID |
| 徽章锚点与线程 | `~/.sepia/books/<book-id>/threads/<page 相对路径>.json`——**book 内不落任何 Sepia 文件**（T-34） |
| 应用配置 | `~/.sepia/config.json` |
| 编辑器会话状态（打开的 tab、光标、滚动） | `~/.sepia/session.json`——是状态不是设置，与配置分开 |
| 引擎配置 | **内存**，启动时注入，不落盘 |
| 凭据 | **Sepia 管控**：API key 类进系统钥匙串、启动时注入、引擎侧零落盘；OAuth 类落 Sepia 自有目录 |
| 主题当前值 | main 进程，首帧前注入 renderer |
| UI 临时态 | renderer 内存，不持久化 |

### 2.3 book 布局

```
<book>/                        # = 文件夹 = git repo = opencode project
  *.md                         # page
  assets/                      # 图片，路径由配置模板决定
```

**book 里只有写作内容，没有任何 Sepia 自己的文件**（T-34）。

应用数据全部收敛在 `~/.sepia`（T-25），不散落到 XDG 各处，也不侵入 book：

```
~/.sepia/
  config.json                  # 应用配置
  session.json                 # 编辑器会话状态（tab / 光标 / 滚动）
  logs/                        # 滚动日志
  engine/{config,data,state,cache}/   # 引擎的四个隔离根（T-11）
  books/
    <book-id>/
      meta.json                # book 路径与名称
      threads/<page 相对路径>.json     # 徽章锚点 + sessionID
      memory/                  # v2
```

## 4. 逐域

### 4.1 引擎嵌入

`vendor/opencode` 为 submodule 并锁 tag。构建期在其 monorepo 根 `bun install` 后跑 `build-node`，产出单文件 ESM 与四份 wasm；electron-vite 把 `virtual:opencode-server` 指向该产物。运行期 `utilityProcess.fork`，在子进程内 `import` 并 `Server.listen`。

产物是**纯 JS + wasm**：wasm 与平台无关，构建管线只需把它们复制到位；两个原生模块已归零——PTY 走"调用即抛错"的桩，文件监听不打包（上游本就优雅降级）。

**边界设置**
- `cwd` = book 根作为兜底，但每个请求显式携带 `directory`。
- **引擎环境完全隔离**：`XDG_CONFIG_HOME` / `XDG_DATA_HOME` / `XDG_STATE_HOME` / `XDG_CACHE_HOME` 四个根全部指向 Sepia 自有目录。引擎的全部路径都由这四个根派生，因此用户机器上装没装 opencode、配了多少 provider / MCP / plugin / agent，与 Sepia 无关。**这些环境变量必须在 fork 时设定**——引擎在模块加载期就把路径算死了，事后再改无效。
- 引擎配置由 Sepia 维护，经 `OPENCODE_CONFIG_CONTENT` 内存注入；隔离出来的配置目录保持为空，book 内也不落配置文件。
- **凭据由 Sepia 管控**（不是「随 opencode」）。token 是用户的东西，不该寄存在另一个应用的文件里——那意味着对方的升级或清理能弄坏你，且写入责任不清。分两类：
  - **API key 类**（绝大多数 provider）：存系统钥匙串，fork 时随内存配置注入引擎（`provider.<id>.options.apiKey`）。**引擎侧零落盘**，隔离目录里不出现凭据文件。
  - **OAuth 类**（订阅式登录）：需要 refresh 与写回，只能持久化在**引擎的隔离目录**内。仍归 Sepia 所有，只是形态是自有目录下的文件。**MVP 不做**——改写文字用 API key 即可。
- **获取途径与共享无关**：首次启动若 Sepia 侧无凭据，可从用户的 opencode 凭据文件**只读导入一次**，导入后即归 Sepia。这是取得方式，不是持续共享；Sepia 永不修改用户 opencode 的任何文件。
- 鉴权走环境变量，不是 `listen` 参数。

**崩溃**：退避重启 ≤3 次 → 进入「Agent 缺席」稳态（顶部细提示线、⌘K 显示缺席文案），写字、保存、commit 全不受影响。

**原则**
- **偏离上游按成本递增的阶梯选手段**：配置层（vite `resolveId`、env）→ 构建脚本层 → patch 文件 → fork 分支 + rebase。patch 不是禁区，是有维护成本的手段——能在配置层解决的别动源码，够不着时就该 patch。
- **patch 必须可复现、可审计**：patch 文件进 Sepia 仓库，prebuild 里 `git apply --check` 硬失败、不静默跳过；绝不在 submodule 里直接改并提交（会丢或变成游离提交）；每次升 tag 必重验。非平凡 patch 累积到一定规模时改用 fork 分支——git 的三方合并比 patch 文件健壮得多。
- `vendor/` 排除在 workspace glob 之外，其 `bun install` 只由构建脚本显式调用。
- 构建期不依赖网络。
- 隔离是单向的：Sepia 不读用户 opencode 的配置，也不写用户 opencode 的任何文件。

### 4.2 数据与版本

**写盘与 commit 是两条时间线，不同频、不同关键性。**

| | 写盘 | commit |
|---|---|---|
| 触发 | 停止输入 800ms | 长静默、定时兜底、markup 成对（下表） |
| 关键性 | **在关键路径上**——用户随时可能 ⌘Q，不能丢字 | **完全异步**，失败不打断写作 |
| 失败表现 | 纸角持久警示点 | ⌘⇧I 留痕，纸面无声 |

顺序恒为 **写盘 → commit**：commit 的是磁盘上的内容，不是内存里的。

**commit 触发**

| 触发 | 条件 | message |
|---|---|---|
| 静默 | 停止输入达到静默阈值（远长于写盘的 800ms） | `sepia: save` |
| 定时 | 定时兜底到点（默认 5min），取与静默先到者 | `sepia: auto` |
| markup 成对 | 落笔前后各一次，**夹出徽章要展示的 diff** | `sepia: pre-markup` / `sepia: markup` |

**写盘频繁而 commit 稀疏**——一次写作应产生个位数 commit，不是几百个。内容无变化则不 commit。结构化信息走 git trailer（`Sepia-Thread`、`Sepia-Page`），**不塞进 subject**，这样 `git log` 可查而 subject 保持可读。

**落笔的时序**：UI 先行——替换文本与徽章上屏在 300ms 内完成；`写盘 → pre-markup commit → 写盘 → markup commit` 这条链在后台按序跑。链失败则徽章仍在、仅 diff 不可用，与 git 缺席时的降级路径一致。

**落笔的撤销语义（T-27）**：落笔是**一次原子编辑**——单个 CM6 transaction 并隔离为独立的 undo 单元，⌘Z 一次撤干净，不会退成半截。撤销后**徽章移出面板，但线程对话保留**（进 F13 的置灰区）——对话是有价值的，用户可能想换个说法再来一次；⌘⇧Z 重做则徽章回来。**git commit 不 revert**：那对 commit 留在历史里，下一次 save commit 自然记录撤销后的状态，历史保持诚实。

**锚点数据不进 git（T-34）**。它记录的是「当时基于哪个 commit、区间在哪、引文是什么」，而对齐算法本来就设计成处理「HEAD 与 anchor.commit 不一致」。**锚点是关于内容的元数据，不是内容本身**——把它一起版本化反而制造悖论：回滚到旧版本时，该用哪个版本的锚点？收敛到 `~/.sepia/books/<book-id>/` 后，三级对齐照常工作，且顺带解决一个实际问题：**成对 commit 夹出的 diff 从此是纯正文 diff**，不再混进锚点 json 的变化。

代价有两条，都要认：**book 不再自包含**（拷到另一台机器只有文字、没有徽章——不过徽章本就是 Sepia 专有概念，别的编辑器也用不了）；**需要 book 身份机制**——`meta.json` 记路径，book 被移动后按路径失联，提供「重新关联」命令即可。MVP 锁单 book，`<book-id>` 可以就是路径的稳定散列。

**锚点**是全项目最难写对的一段：会话内编辑用 CM6 位置映射 → 打开文件时若 HEAD 与锚点 commit 不一致，用 git diff 的 hunk 平移区间 → 失败退引文加前后文模糊匹配 → 再失败降级孤儿徽章。独立成纯函数模块，参数进配置，用真实文章标定。

**原则**
- **git 操作串行化**：GitService 内部一条队列，杜绝并发 commit 撞 `index.lock`。
- **commit message 不调模型生成**。它必须在离线、引擎缺席、300ms 内完成——违反不变量 1 的便利不要。
- `.sepia/` 下所有 json 一律 tmp 文件 + rename 原子写。
- md 的读写字节级 round-trip。
- 不复制引擎的消息数据。
- 锚点宁可保守转孤儿——误匹配（徽章挂到不相干段落）比孤儿更糟。

### 4.3 Agent 边界

renderer 内唯一的 agent 切面是 **AgentBridge 五方法**：`openThread` / `send` / `stream` / `interrupt` / `listModels`。内部用 `@opencode-ai/sdk`，端点映射以锁定 tag 的 OpenAPI 为准。

协议要点：只有字符串字段走增量拼接，其余整 part 替换；SSE 有心跳，用于区分「模型停了」与「连接死了」；未知事件类型一律忽略。

**上下文永不缓存，因此永不失效。** 模型不持有文章副本——每一轮 markup 都当场从编辑器现值取一次（选区 + 前后文 + 显式 `@content`）随请求发出。用户在两次 ⌘K 之间改了多少字都无关紧要，下一次取的就是新值。这是「上下文显式喂、不靠 session 累积」的技术收益：**无缓存即无失效**。

唯一的例外是**同线程追问**：同一 session 里已经躺着上一轮发过去的旧原文。因此每一轮都重发当前文本快照，并由 system prompt 明确「以本轮提供的原文为准」。

**落笔是有条件的写入。** diff 是针对"提交那一刻的文本"算出来的，而生成期间用户可以继续写字。所以落笔前必须校验：目标区间的当前文本是否仍等于提交时的快照？不等则**不落笔**，提示用户重来或手动处理。覆盖用户刚写下的字，是对「AI 不抢笔」最严重的违反。

**原则**
- 组件只能经 AgentBridge 碰 agent，不得直接请求引擎。
- 每个请求显式带 `directory`，不赌默认值。
- 上下文当场取值，不缓存、不预先塞进 session。
- 落笔前做 compare-and-swap 校验，不匹配即中止。
- 五方法是换引擎的唯一切面。扩方法前先问能否用现有五个表达。


### 4.3b markup 延迟

**先看时间花在哪**——这决定了哪些手段有用：

| 段 | 归属 | 我们能做什么 |
|---|---|---|
| 取选区、组装请求 | 我们 | 毫秒级，无优化余地 |
| 建 session | 我们 | **预热即可消除** |
| 引擎 → provider 网络往返 | 环境 | 不可控（代理环境下这段可能是最大变量） |
| 模型 TTFT | 模型 | **换小模型是唯一有效杠杆** |
| SSE 回流 + 上屏 | 我们 | 首 token 即上屏，勿缓冲 |

**诚实的判断：3s 里的大头不在我们手里。** 我们的职责是三件——不给它增加固定开销、让等待"感觉"短、以及把换小模型这条路留通。

**MVP 就要建好结构的**（漏了以后要重构）：

1. **延迟打点 t0–t5**：提交 / 请求发出 / 首字节 / 首 token / 完成 / 落笔。**没有打点，后面一切优化都是盲猜**——这条比任何具体优化都重要。口径写死在代码里，进 smoke 断言。
2. **session 预热**：引擎就绪时预建空 session，把建 session 的往返从关键路径上摘掉。预热池大小是配置项，MVP 取 1。
3. **system prompt 是常量**：可变内容一律进 user message。这既让行为可预测，也是 provider prompt caching 的前提（缓存要求前缀逐字节一致）。**若把时间戳、页面名塞进 system prompt，缓存永远不会命中。**
4. **用途 → 模型的映射**（D-36 的用途指派表）：即使 MVP 只配一个模型，这层映射也要在——"快速改写用小模型"是降 TTFT 最有效的手段，事后加会牵动整条调用链。
5. **上下文最小化**：只带选区与前后文（D-31）。prompt 越短 TTFT 越低——这既是产品决策也是性能手段。
6. **首 token 即上屏**：流式链路不做任何缓冲；生成中的家具在提交瞬间就位（D-29），不等首 token。

**可以后面做的**：热 session 池扩容 ｜ 对齐 provider 的 prompt caching（短 prompt 通常够不到缓存门槛，收益有限）｜ 多模型竞速取先到（花两份钱，不划算）｜ 引擎侧连接复用核验 ｜ 推测性预取（用户按下发送前不能发——会花钱且未必用）。


### 4.3c 任务与上下文

不同任务要的上下文差别很大——文本改写要选区与邻近段落，图片取名要图片本身加插入点周围文字，语音转写压根不要文档。**若把上下文规则写死在每个功能里，加一个任务就要在调用、UI、写入三处各改一遍。**

**任务是一个四元组**，注册在一张表里，加任务 = 加一条配置：

```
任务类型 → { 模型, 上下文策略, system prompt, 输出去向 }
```

- **模型**：来自 D-36 的用途指派表（按能力标签过滤）。
- **上下文策略**：取材范围与预算，见下。
- **system prompt**：常量（T-32 纪律 21）。
- **输出去向**：决定 UI 与写入路径——**正文替换**（走落笔的 CAS 校验）/ **元数据**（写 frontmatter）/ **文件名**（如图片取名）/ **只显示不写入**。这一维最容易被忽略，但它决定了结果落在哪里；缺了它，每加一个非改写类任务都要动写入层。

**上下文组装器接受一个「块」列表**，而不是一个字符串。MVP 只填三种块：选区、邻近正文、`@content` 显式引用。将来要加「本篇已落笔摘要」「记忆」只是多一种块，组装器不变。

**取材与预算**。整篇 2 万字约 3 万 token——**带整篇与「首 token < 3s」直接冲突**，且会稀释模型注意力。MVP 按**距离衰减**取材：选区 → 所在段 → 前后各 N 段 → 篇首（标题与 frontmatter，用于全局定位），到预算上限即**硬截断**，不做摘要、不做检索。上限是配置项。

> **一处需产品裁决**：设置清单里「上下文范围」默认值是**整篇**，与上述预算冲突。建议默认改为「选区 + 邻近」，整篇作为可选项。

**多轮之间不累积**。一篇文章里做过五次 markup，第六次**不带**前五次的痕迹——每次干净、可预测、快且便宜（D-12 / D-31）。代价是模型可能重复建议已被拒绝的改法；若这成为真实痛点，加一种「本篇已落笔摘要」块即可，组装器不用改。

**同线程追问**（F10）：session 里已有上一轮的旧原文，故每轮重发当前选区快照并由 system prompt 声明「以本轮提供的原文为准」（T-22）。前后文只在首轮发、追问时省略，属可后置的优化。

**MVP 建结构 / 可后置**

| MVP 就要有 | 可以后面做 |
|---|---|
| 任务四元组注册表 | 已落笔摘要注入 |
| 块式上下文组装器 | 长上下文摘要与压缩 |
| 距离衰减取材 + 预算硬截断 | 检索式取材（相关段落而非邻近段落） |
| 输出去向的分派 | 追问时省略未变的前后文 |
| 每轮重发当前快照 | 记忆注入（v2） |

### 4.4 渲染层

**编辑器**：CodeMirror 6，源码态 live preview，元素级揭示。**MVP 覆盖全部 markdown 语法**——半套 live preview 比没有更糟：一部分渲染、一部分不渲染，纸面就成了既非源码也非成品的中间态。

「渲染」按语法类别分四种含义，机制与代价差一个量级：

| 类 | 语法 | 渲染的含义 | 机制 |
|---|---|---|---|
| **A 行内标记** | 强调、加粗、行内代码、删除线、链接、自动链接、行内公式、转义、硬换行 | 显示为效果，**光标进入该元素才露出标记** | **mark / inline-replace 二式** + 光标区间判定（行内公式是 replace + KaTeX widget，与表格同族，Stage 2 修订）。写完第一个，其余是**配置表** |
| **B 块级排版** | 标题、引用（含嵌套）、无序/有序列表、任务列表、分隔线、frontmatter | 行首标记隐藏 + **视觉缩进对齐**，文本一个字节不动 | 行装饰 + padding。**最麻烦的一类**，见下 |
| **C 块级 widget** | 表格、块级公式、textdiagram、图片 | 失焦渲染成图/表，光标进入变回源码 | 块 widget（L1） |
| **D 不渲染** | HTML 块与裸行内 HTML、缩进式代码块 | 按普通文本呈现，可加语法高亮 | — |

**B 类为什么最麻烦**：列表与引用的缩进必须**视觉实现**而非改写文本——不能重新缩进字节（违反不变量 2），只能靠 padding 与 hanging indent 把 `- ` 藏掉并对齐。嵌套层级、有序列表的宽度变化（`9.` 与 `10.`）、软换行后的续行对齐，都要算。这是 CM6 live preview 公认最费工的部分。

**D 类为什么排除**：任意 HTML 渲染带来安全与布局不可控（不变量里没有为它兜底的机制）；缩进式代码块与列表内缩进天然歧义，判错会毁掉排版。两者按源码呈现是更诚实的选择。

**流式**：解析层负责补全未闭合语法与块级 memo；揭示节奏为 24ms 批次、按词与标点边界 snap、无逐字补间；`prefers-reduced-motion` 命中则整块秒显。四条稳定性不变量：**冻结即定、结构块绝不闪 raw、揭示单调只增、节奏与 token 到达率解耦**。

**CM6 接入的结构硬约束（Stage 2 实测得出，与下面的字节硬约束并列）**：
① **块级 replace decoration 只能来自 StateField**——ViewPlugin 提供直接 `RangeError`，装饰引擎必须分两层（行内层随视口走 plugin、块级层全文档走 field）；
② **跨换行的 replace 不许来自 plugin**（HardBreak 节点含换行符，隐藏范围要夹到行尾）；
③ **⌘⇧V 在 Chromium 不派发 paste 事件**（它是编辑命令），粘贴逃生舱必须自己读剪贴板。

**CM6 接入的字节硬约束（不变量 2，Stage 1 实测得出）**。CodeMirror 6 会**静默规范化换行**，这是不变量 2 最现实的一条威胁，且它在两层上都成立：

- `EditorState.create()` 默认按 `DefaultSplit = /\r\n?|\n/` 拆行——**CRLF 文件读进去就没有 CR 了**；
- 即便显式设了 `EditorState.lineSeparator` facet，**`state.doc.toString()` 仍恒用 LF 拼行**：`Text.sliceString(from, to, lineSep = "\n")` 的默认值是硬编码的，与 facet 无关，而 `toString()` 不传它。只有 `state.sliceDoc()` 才传 `state.lineBreak`。

**两个 API 差一个字符，后果是用户整个文件被静默改写。** 因此三条硬约束，对所有 stage 有效：

1. 读入前先检出换行风格与 BOM，并在写出时原样还原；
2. `baseExtensions` 恒设 `lineSeparator`；
3. **取全文一律经统一封装（`readDoc()`），不许直接调 `doc.toString()`** ——按 002 §2.1 的模式，让调用方没有写错的机会。

守卫是「读入—写出字节保真」单测（001 §6，Stage 1 起），fixture 须覆盖 LF / CRLF / CR / 无尾换行 / 混用换行 / BOM / 非 ASCII / 超长行 / 空文件。**Stage 2 起接装饰时，这三条不因新增扩展而放松。**

**主题**：CSS 自定义属性是唯一真相。shadcn 变量组加 Sepia 纸的语义变量；CM6 主题与语法高亮写 `var(...)`，因此换主题只换变量、不重建扩展，光标与滚动位置不丢；mermaid 从 computed style 读同一组变量。

**代码高亮有两处，必须由同一份色板派生**：纸上的代码块由 CM6 自己高亮；markup 浮层与线程回放里的代码块由流式 markdown 库高亮（其内部用 Shiki——VS Code 同款高亮器，特点是**把颜色内联进 HTML**，因而吃不到 CSS 变量，需用它的双主题输出模式）。两处不同源就会出现「同一段代码在纸上和在浮层里两个样」。**可选的简化**：Agent 面板里本就很少出现代码块，若确认不需要，关掉该库的高亮即可——两个高亮器的一致性问题随之消失。缩放走主进程 API。

**剪贴板（T-28）**：复制时同时写两种格式——`text/plain` 放 md 源码（给代码、终端、其他编辑器），`text/html` 放渲染态（**粘进微信公众号编辑器或 Word 直接是富文本**，这是发文场景的刚需）。粘贴默认智能转换：剪贴板含 HTML 时转成 md 插入，只有纯文本时原样插入；⌘⇧V 是「粘贴为纯文本」的逃生舱。转换产生的是**新字节**，不改写已有内容，不触碰不变量 2。

**多语言**：界面文案集中在 `copy/`，跟随界面语言；Agent 文案（情境动词、system prompt）跟随**正文**语言——动词属文本域，家具属应用域。system prompt 里「输出与原文同语言」Day-1 就写。

**原则**
- composition 活跃期间冻结装饰更新，尤其禁止改动光标前方的 replace decoration 与 inline widget。
- 组件与 CM6 扩展不得出现字面色值。
- 组件不得出现用户可见的字面串。
- command registry 存 key 不存字符串；所有 UI 动作先注册命令再绑键，按钮本身也走 `execute`——一种契约，不是两种。

### 4.4b 结构化元素与 WYSIWYG 路线

散文用源码态揭示已经够好（Obsidian 千万用户量级验证），**WYSIWYG 的真实优势集中在二维结构**：表格、公式、图表——纯文本编辑它们是公认痛点。

所以路线不是「哪天整篇换成 WYSIWYG」，而是**把 WYSIWYG 关进 widget 里，按元素逐个解锁**：

- 一维散文 → 源码态 + 元素级揭示，字节不动。
- 二维结构 → widget 内提供所见即所得的编辑器，编辑结果**只序列化回它自己那一段**的字节，全文其余部分一个字节不改。

**这不需要新机制**——textdiagram 组件已经是这个模式（编辑时代码、失焦渲染成图），表格只是把它反过来：平时是表、编辑时给二维编辑器。同理适用于公式。

**三个层级要分清**，它们成本差一个量级：

| 层级 | 看到什么 | 机制 | MVP |
|---|---|---|---|
| L0 纯源码 | 始终是 `\| a \| b \|` | 无装饰 | — |
| **L1 失焦渲染** | 光标不在其中 → 渲染成真表格 / 真公式；光标进入 → 变回源码编辑 | 与 textdiagram 同构的 widget | **✅ 表格与公式都进 MVP** |
| L2 所见即所得编辑 | 在渲染态里点单元格、加行加列；可视化编辑公式 | 二维编辑器 + 序列化回本段 | 依痛感排后续 |

L0 → L1 的体验差距远大于 L1 → L2：**只读渲染就已经解决了「看不清结构」这个主要痛点**，单元格编辑属锦上添花。而 L1 的边际成本很低——块 widget 的机制因 textdiagram 与图片本来就要建，表格和块级公式只是第三、第四种。

**行内公式是唯一的例外**：`$x$` 需要**行内 replace decoration**，正落在 T-17（composition 期间冻结装饰）那条规则的考验场上；块级公式 `$$…$$` 独占一行，无此问题。因此行内公式是 CM6 × 中文 IME 这项检查里最该早验的用例。

**它为什么不破坏不变量 2**：widget 里的改写是**用户主动编辑的结果**，落在它自己那一段区间内，不是保存时对全文的偷偷规范化。这正是不变量 2 说「未触及的字节逐字节保留」而不是「永不改写」的原因。

### 4.9 文件、会话与窗口

**监听与冲突（T-26）**。用 **chokidar v4** 监听 book。

选它而不是裸 `fs.watch`，有两条实在理由：①**v4 已无原生模块**（依赖数从 13 降到 1，fsevents 移除），所以 T-18 辛苦归零的原生依赖不会长回来、CI matrix 也不必退回四个 runner；②它有 **`atomic` 选项**，专门处理「编辑器用临时文件加改名来保存」这件事——把 100ms 内的删除加重建归并成一次 `change`，而不是抛出一对 `unlink` + `add`。**这正是我们自己的写法**（`.sepia` 下 json 一律 tmp + rename），也是 vim、VS Code 等外部编辑器的写法；裸 `fs.watch` 在这种情况下给出的事件跨平台不一致，是一类典型的疑难 bug。

裸 `fs.watch` 的另外两个坑：递归监听在 Linux 上是后来才补的，且底层按目录逐个挂 inotify，**大 book 会撞 `max_user_watches` 上限**；网络盘上事件常常不来。

因此监听不是唯一手段，**必须有对账兜底**：窗口 focus 时按 mtime / size 快速比对。日常靠事件、切回来时校准；监听整体失效（限额撞满、网络盘）时降级为「仅 focus 对账」，写作不受影响。轮询模式（`usePolling`）作为网络盘的逃生舱留在配置里。

- **自写回声必须抑制**：Sepia 自己的写盘与 git 操作会触发事件，需按「路径 + 刚写入的 mtime」过滤，否则保存一次就自我重载一次。
- **冲突策略**：外部变更到达时，若该 page 无未落盘改动 → 重载并尽量保住光标位置；**若有未落盘改动 → 先立即落盘**（用户刚敲的字优先级最高），再把外部版本作为提示交给用户选择（保留我的 / 用外部的 / 看 diff）。**绝不静默覆盖用户的字节**。
- 外部变更也是锚点重对齐的触发点。

**单实例 + 多窗口（T-29）**。第二次启动时抢不到实例锁的进程，把自己的 argv 交给已运行实例后退出，由后者开新窗口——这是 VS Code 的模型。收益是 git 队列、`session.json` 与 `threads/*.json` 的写入天然串行，不必再防跨进程竞争。窗口行为遵循各平台惯例：mac 关闭最后一窗不退出应用，Windows / Linux 退出。

**游离 page（T-30）**。Sepia 也要能当纯 markdown 编辑器：双击 .md、拖到应用图标、命令行传参都能直接打开，哪怕它不属于任何 book。此时按能力降级——无 git 则无版本与徽章 diff，无 book 则 `@` 引用不可用；**纸本身完全可写**，与不变量 1 同构。

**首次运行**。onboarding 就在主页：无 book 时主页给「选择文件夹作为 book」与「打开一个 .md」两条路，不做独立引导流程。窗口先出、纸未就绪的那一小段显示 loading 态——**它必须已经是正确主题**，不能白底闪一下（见 §4.7）。

**文件管理**。新建 / 重命名 / 移动 / 删除进 MVP，删除走系统回收站。**重命名后更新内部链接改为用户主动发起的命令**，不做自动开关——它要改写其他文件的字节，只有在用户明确要求时才合法，且必须列出将改动哪些文件、并入同一个 commit（T-31）。

**拖拽按落点分工，两条互不重叠**：

| 落点 | 接受 | 行为 |
|---|---|---|
| **编辑区** | 图片、GIF | 落盘到图片目录并插入 `![]()`，与 ⌘V 粘贴同一条路径 |
| 编辑区 | 其他一切（含 .md、视频） | **无效，不做任何事** |
| **窗口空白处 / 应用图标 / 命令行参数** | .md | 打开为 page（属于当前 book 则正常，否则走游离模式 T-30） |

视频不支持——markdown 无原生视频语法，只能写 `<video>` 而 HTML 属 D 类不渲染，为它单开 widget 不值当（已进非目标）。

**保存失败**。终态：提示 → 自动重试 3 次 → 仍失败则拦截关闭，由用户确认是否强制关闭。这是 ⌘Q 无对话框规则的唯一例外。

**分两档落地**，因为保存路径从 Stage 1 就存在，而完整重试在 Stage 7——中间六个 stage 不能没有说法：**Stage 1 起保证「失败可见、不静默、不假装成功」**（有可见提示，脏标记保留）；**Stage 7 补完整的重试与拦截关闭**。不写清这一档，Stage 1 要么过度实现，要么静默吞掉错误。

**查找替换**。篇内 ⌘F 查找、⌘⌥F 替换，用 CM6 的 search 能力但**自绘 UI** 以统一主题、快捷键与文案；book 级全文搜索仍在非目标。

### 4.5 配置

单一 `~/.sepia/config.json`（与 T-25、纪律 20 一致——**应用自有文件不散落 XDG**；此处原写 `~/.config/sepia/`，2026-08-04 订正），字段树镜像设置清单的四个一级，全量默认值集中在 `defaults.ts`。文件只存与默认值的差异，带 `version`，未识别字段保留。

**这里描述的是终态字段树，不是任何一个 stage 的建设清单。** 各 stage 只往 `defaults.ts` 加**自己真正读取**的字段——提前铺满会逼着当前 stage 替后面的 stage 裁默认值（例如「上下文范围」的默认值属 Stage 4，不该在 Stage 1 被顺手定下）。同 001 §1 仓库结构图的 `[Sn]` 标注。

MVP 无设置 UI——**改配置即改这个文件**，这也是后续功能开关的入口：新功能先进 `defaults.ts` 加字段，UI 后到。配置内永不包含权限类字段。

### 4.6 安全

`contextIsolation: true` / `sandbox: true` / `nodeIntegration: false` / CSP 限制 `connect-src` 为 self 与本地引擎。preload 只暴露 contextBridge 白名单，命名 REST 风格。引擎绑 127.0.0.1，随机密码 Basic Auth，CORS 只放 renderer origin。

**renderer 用自定义特权 scheme 加载**，该 origin 写进 CORS——`loadFile` 会让 Origin 为 `null`，跨到本地引擎的请求将被拒。

**原则**：preload 白名单的任何变更由 CI 守卫比对，白名单膨胀即阻塞。

### 4.7 启动

```
t0 进程启动
├─ 同步路径（预算 <1s）：创建窗口 → 读上次 page 一个文件 → CM6 就绪、光标就位
└─ 异步路径（一律不挡光标）：引擎启动 ∥ git status ∥ 文件树索引 ∥ config watch
```

主题必须在首帧之前落到 `<html>`，且窗口创建时带 `backgroundColor`——否则白底闪一下再变暗，正砸在「白纸秒开」的观感上。

**打点口径（t0–t5）**。纪律 12 的强制方式是打点断言，所以口径必须是设计真相而非各 stage 各自定义。六个点的定义写进 `core/types`，**改口径的那次提交必须同时改断言与预算表**。

| 点 | 位置 | 含义 |
|---|---|---|
| t0 | `main/index.ts` 第一行可执行语句 | 进程启动。**不是 `app.whenReady`**——那已经晚了几十到上百毫秒 |
| t1 | `app.whenReady` 回调进入 | Electron 就绪 |
| t2 | `new BrowserWindow()` 返回 | 窗口对象已建，尚未可见 |
| t3 | `ready-to-show` 触发、`show()` 之后 | **窗口可见**，主题属性必须已在 `<html>` 上 |
| t4 | renderer 侧 page 文件内容到手 | 纸的字节已到 |
| t5 | CM6 `EditorView` 就绪且光标落位 | **可写**。t0→t5 即「冷启动 <1s」所指 |

预算：t0→t5 < 1s、t0→t3 < 500ms、t3→t5 < 500ms。**测法以打包产物为准**（不是 dev），常温冷启动连跑 10 次取 P50 与 P90，未签名 macOS 的首次 Gatekeeper 验证单独标注、不混入统计。

**原则**
- 启动同步路径上只允许窗口、单文件与 CM6，其余一律后置。
- renderer 入口 bundle 保持小，重组件按交互懒加载。
- 第一天就埋性能打点，预算做成可断言项。

### 4.8 构建与发布

**多包仓库（T-06）**，包管理与任务编排用 **bun workspaces + catalog + turbo**——与 opencode 同一套，而非 pnpm。三条理由：①Sepia 本来就必须装 bun（vendor 的 `build-node` 是 bun 脚本），用 pnpm 等于在同一个仓库里放两个包管理器、两份 lockfile；②**catalog 正好解决一个真问题**——`@opencode-ai/sdk` 必须与 vendor 锁同 tag，catalog 让这类版本集中钉死而不是散在各包里；③electron-builder 收集生产依赖时与 pnpm 默认的隔离式 `node_modules` 有已知摩擦（通常要 `node-linker=hoisted`），bun 默认即扁平。

**包的划分与依赖方向**——包边界是比 lint 更硬的约束，因此按「谁能依赖什么」来切，而不是按功能大小：

**为什么用包边界而不是 VS Code 式的「目录分层 + lint」**：两者的差别只有强制力的层级。lint 规则可被 `eslint-disable` 绕过，且前提是写代码的人知道有这条规则；而 `core` 的 `package.json` 没声明 `electron`，就是 import 不到——**编译期的物理约束，不是约定**。本项目由 AI 实施且无 code review 兜底，能交给机器守的边界应尽量交出去。VS Code 敢靠约定，是因为它有几百个 reviewer 与十年团队记忆。

**包的准入判据**——满足至少一条才切，「代码多」与「功能不同」都不是理由：**(a)** 运行环境约束不同（能否碰 DOM / Electron）｜**(b)** 有独立构建产物或发布需求 ｜**(c)** 有第二个消费者。

| 包 | 内容 | 硬约束与判据 |
|---|---|---|
| `core` | 锚点对齐、config merge 与默认值、文案、跨进程契约类型 | **不依赖 Electron、不依赖 DOM，且外部依赖趋近于零**。(a) |
| `editor` | CM6 扩展与 widget：A/B/C 类装饰、markdown 结构判定、IME 规则、剪贴板、查找替换 | 依赖 DOM 与 `core`，**不依赖 Electron**——能在纯 Vite 里开发。(a) |
| `agent` | AgentBridge 五方法、任务四元组注册表、上下文块 | 只依赖 `core` 与 HTTP，**不碰 DOM**——mock SSE 单测不必起浏览器。(a) |
| `ui` | 主题变量、shadcn 组件、基础件 | **叶子，零内部依赖**：组件只收原始 props，不知道领域概念。(a)(c) |
| `app` | Electron：main / preload / renderer 的装配 | **唯一允许 import `electron` 的包**；领域组件也放这里 |

```
core ──→ editor ─┐
  └───→ agent ───┼──→ app
        ui ──────┘
```

**层次必须保持线性，不许出现菱形或环**（借自 VS Code 的 `base → platform → editor → workbench`）。一旦 `editor` 想 import `agent`，说明该把那部分能力上提到 `app` 装配，而不是在中间层横向连线。

三条来自 opencode 的实测经验：**①组件库是叶子**——它的 `ui` 零内部依赖，组件不知道领域，因此能独立预览、不随领域类型变动重编译；**②契约与纯函数包保持零外部依赖**——`markdown` 结构判定要用 lezer，故归 `editor` 而非 `core`，让 `core` 真正轻；**③不设 `util` 包**——没有边界定义的包会吸走一切，最后所有包都依赖它，等于没切。

**不切的两个也记下理由**：不设垃圾桶包；不单设领域组件包——opencode 的 `session-ui` 存在是因为它有 web、desktop、storybook 三个消费者，Sepia 只有一个 `app`，等真出现第二个消费者再拆。

收益是可测性：`core` 与 `agent` 不碰 DOM 与 Electron，单测直接跑；`editor` 不碰 Electron，能在浏览器里开发——**CM6 × 中文 IME 的验证正好在这里做，不必起应用**。**反悔通道**：从多包退回单包分层是容易的（合并目录 + 加 lint 规则），反过来才痛，所以先多包是安全方向。

`vendor/opencode` 不属于任何 workspace glob（它在 `packages/` 之外），其 `bun install` 只由构建脚本显式调用。两个 workflow：`ci`（lint、typecheck、Vitest、白名单守卫）与 `build`（一台 mac 出双 arch，一台 Linux 出 linux 与 win——dmg 与公证是 mac-only，mac runner 省不掉）。main push 自动覆盖发 alpha prerelease，tag 触发正式 release。Day-1 产物未签名。
